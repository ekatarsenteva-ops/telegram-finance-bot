## Слой данных (PostgreSQL / Supabase)

### Основные таблицы

```sql
-- Объекты (Организации)
CREATE TABLE organizations (
    id SERIAL PRIMARY KEY,
    name VARCHAR(255) NOT NULL UNIQUE,  -- "Школа языков", "Недвижимость"
    description TEXT,
    created_at TIMESTAMP DEFAULT NOW()
);

-- Пользователи
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    telegram_id BIGINT NOT NULL UNIQUE,
    username VARCHAR(255),
    role ENUM('owner', 'admin', 'coordinator', 'viewer') DEFAULT 'coordinator',
    created_at TIMESTAMP DEFAULT NOW()
);

-- Категории (привязаны к объектам)
CREATE TABLE categories (
    id SERIAL PRIMARY KEY,
    organization_id INTEGER NOT NULL REFERENCES organizations(id),
    name VARCHAR(255) NOT NULL,
    type ENUM('income', 'expense') NOT NULL,
    created_at TIMESTAMP DEFAULT NOW(),
    UNIQUE(organization_id, name)  -- одна категория на объект
);

-- Контрагенты (глобальные, без привязки к объекту)
CREATE TABLE counterparties (
    id SERIAL PRIMARY KEY,
    name VARCHAR(255) NOT NULL UNIQUE,  -- "Петя", "Иван", "Управляющая компания"
    notes TEXT,
    created_at TIMESTAMP DEFAULT NOW()
);

-- Транзакции (основная таблица)
CREATE TABLE transactions (
    id SERIAL PRIMARY KEY,
    user_id INTEGER NOT NULL REFERENCES users(id),
    organization_id INTEGER NOT NULL REFERENCES organizations(id),
    type ENUM('income', 'expense', 'incoming_payment') NOT NULL,
    amount NUMERIC(12, 2) NOT NULL,
    currency VARCHAR(3) DEFAULT 'RUB',
    date DATE NOT NULL DEFAULT CURRENT_DATE,
    category_id INTEGER REFERENCES categories(id),
    counterparty_id INTEGER REFERENCES counterparties(id),
    
    -- Флаги для взаимозачётов
    is_offset BOOLEAN DEFAULT FALSE,  -- это ли расход для взаимозачёта?
    offset_status ENUM('pending', 'applied') DEFAULT NULL,
    
    -- История парсинга (для аудита)
    raw_ai_log JSONB,  -- {input_text, ai_response, timestamp}
    
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);

-- Участники групповых расходов (отслеживание возврата)
CREATE TABLE expense_participants (
    id SERIAL PRIMARY KEY,
    transaction_id INTEGER NOT NULL REFERENCES transactions(id) ON DELETE CASCADE,
    person_name VARCHAR(255) NOT NULL,
    amount NUMERIC(12, 2) NOT NULL,  -- сумма, которую должен вернуть
    is_paid BOOLEAN DEFAULT FALSE,  -- вернул ли свою долю?
    paid_date TIMESTAMP DEFAULT NULL,  -- когда вернул?
    paid_amount NUMERIC(12, 2) DEFAULT NULL,  -- сколько вернул (если не полная сумма)
    
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);

-- Взаимозачёты (отслеживание статуса)
CREATE TABLE counterparty_offsets (
    id SERIAL PRIMARY KEY,
    source_transaction_id INTEGER NOT NULL REFERENCES transactions(id),
    counterparty_id INTEGER NOT NULL REFERENCES counterparties(id),
    amount NUMERIC(12, 2) NOT NULL,  -- сумма зачёта
    status ENUM('pending', 'applied', 'cancelled') DEFAULT 'pending',
    applied_to_transaction_id INTEGER DEFAULT NULL REFERENCES transactions(id),
    created_at TIMESTAMP DEFAULT NOW()
);
```

### 2. AI-Оркестратор (Claude API)

Промпт для Claude API:

```python
SYSTEM_PROMPT = """
Ты помощник для учета финансов. Твоя задача - парсить операции из текста.

Твой выход всегда JSON с полями:
{
  "transaction_type": "income" | "expense" | "incoming_payment",
  "amount": number,
  "currency": "RUB" | "USD" | "EUR",
  "date": "YYYY-MM-DD" (сегодня если не указано),
  "counterparty": string | null,
  "organization_id": 1 | 2 (если невозможно определить → null),
  "category": string | null,
  "is_offset": boolean (есть ли в тексте "зачет в", "вычту", "скидка на"?),
  "split_participants": [
    {"name": string, "amount": number | null}
  ] | null  (если деление расхода),
  "confidence": 0-100  (уверенность парсинга),
  "needs_clarification": [field1, field2, ...],  (какие поля нужно уточнить?)
}

Правила парсинга:
1. Если текст содержит "пришло", "внес", "перевел" → income или incoming_payment
2. Если "расход", "купил", "потратил" → expense
3. Если "зачет", "вычту", "скидка на" → is_offset = true
4. Если "делим на N", "поровну на", "на каждого" → создать split_participants
5. Если не указан объект, но упомянута "школа", "язык" → organization_id = 1 (Школа)
6. Если упомянута "недвижимость", "аренда", "квартира", "дом" → organization_id = 2 (Недвижимость)

Примеры:
- "Пришло 15000 от Пети" →
  {transaction_type: "income", amount: 15000, counterparty: "Петя", needs_clarification: ["organization_id"]}

- "Внесли аренду за август, 50 тыс" →
  {transaction_type: "incoming_payment", amount: 50000, category: "Аренда", organization_id: 2, needs_clarification: ["counterparty"]}

- "Купили материал за 6 тыс, зачет в аренду" →
  {transaction_type: "expense", amount: 6000, is_offset: true, organization_id: 1, needs_clarification: ["category"]}

- "Пикник 9 тыс, делим на Иву, Марию, Петра поровну" →
  {transaction_type: "expense", amount: 9000, split_participants: [{name: "Ива", amount: 3000}, ...], needs_clarification: ["category"]}
"""

USER_PROMPT_TEMPLATE = "Распарси операцию: {text}"

# Использование:
response = client.messages.create(
    model="claude-3-5-sonnet-20241022",
    max_tokens=1000,
    system=SYSTEM_PROMPT,
    messages=[{"role": "user", "content": USER_PROMPT_TEMPLATE.format(text=user_text)}]
)

parsed = json.loads(response.content[0].text)
```

### 3. Dialog Flow (уточнение недостающих полей)

```python
async def clarify_missing_fields(parsed_data, user_id):
    """
    Если parsed_data.needs_clarification не пусто,
    задаём один вопрос за раз.
    """
    
    CLARIFICATION_PROMPTS = {
        "organization_id": "Для какого объекта: Школа (1) или Недвижимость (2)?",
        "counterparty": "Уточните, пожалуйста, контрагента (кто внес/кто получил)?",
        "category": "Выберите категорию операции из справочника...",
        "amount": "Уточните сумму (цифра в рублях)?",
    }
    
    for field in parsed_data['needs_clarification']:
        question = CLARIFICATION_PROMPTS.get(field, f"Уточните {field}")
        await send_telegram_message(user_id, question)
        answer = await wait_for_user_input(user_id, timeout=300)  # 5 минут
        parsed_data[field] = parse_answer(field, answer)
    
    return parsed_data
```

### 4. Validation & Business Logic

#### 4.1 Offset Manager (взаимозачёты)

```python
async def handle_offset_expense(transaction_data):
    """
    Если is_offset = true, создать запись в counterparty_offsets
    """
    offset = {
        "source_transaction_id": transaction.id,
        "counterparty_id": transaction.counterparty_id,
        "amount": transaction.amount,
        "status": "pending"
    }
    db.insert("counterparty_offsets", offset)

async def apply_offset_to_incoming_payment(payment_transaction_id):
    """
    Если это incoming_payment и есть открытые зачёты,
    предложить их применить
    """
    counterparty_id = payment.counterparty_id
    open_offsets = db.query("""
        SELECT * FROM counterparty_offsets 
        WHERE counterparty_id = %s AND status = 'pending'
    """, counterparty_id)
    
    total_offset = sum(o.amount for o in open_offsets)
    
    if total_offset > 0:
        ask_user = f"Применить взаимозачёты на сумму {total_offset}₽?"
        if user_confirms():
            # Уменьшить платёж
            payment.amount -= total_offset
            
            # Обновить статус зачётов
            for offset in open_offsets:
                db.update("counterparty_offsets", 
                    {"status": "applied", "applied_to_transaction_id": payment.id})
```

#### 4.2 Expense Splits Manager (групповые расходы)

```python
async def handle_grouped_expense(transaction_data):
    """
    Если split_participants не пусто, создать записи в expense_participants
    """
    transaction_id = create_transaction(transaction_data)
    
    for participant in transaction_data['split_participants']:
        db.insert("expense_participants", {
            "transaction_id": transaction_id,
            "person_name": participant['name'],
            "amount": participant['amount'],
            "is_paid": False
        })

async def mark_participant_paid(transaction_id, person_name, amount_paid=None):
    """
    Обновить статус возврата денег для участника
    """
    participant = db.query("""
        SELECT * FROM expense_participants 
        WHERE transaction_id = %s AND person_name = %s
    """, transaction_id, person_name)
    
    if amount_paid is None:
        amount_paid = participant.amount  # полная сумма
    
    db.update("expense_participants", {
        "is_paid": True,
        "paid_date": now(),
        "paid_amount": amount_paid
    }, id=participant.id)

async def get_debt_summary():
    """
    Вернуть список всех открытых долгов
    """
    return db.query("""
        SELECT 
            ep.person_name,
            SUM(ep.amount) as total_debt,
            COUNT(CASE WHEN ep.is_paid = false THEN 1 END) as pending_returns,
            ARRAY_AGG(DISTINCT t.type) as expense_types
        FROM expense_participants ep
        JOIN transactions t ON ep.transaction_id = t.id
        WHERE ep.is_paid = false
        GROUP BY ep.person_name
    """)
```

### Telegram Bot API (Webhook)

```python
from flask import Flask, request
from telegram.bot import Bot

app = Flask(__name__)
bot = Bot(token=TELEGRAM_BOT_TOKEN)

@app.route('/webhook', methods=['POST'])
async def webhook():
    """
    Получить обновление от Telegram,
    обработать и отправить ответ
    """
    update = request.get_json()
    
    if 'message' in update:
        message = update['message']
        user_id = message['from']['id']
        text = message.get('text', '')
        voice = message.get('voice')
        
        # Маршрутизация
        if text.startswith('/'):
            await handle_command(user_id, text)
        elif voice:
            transcript = await transcribe_voice(voice['file_id'])
            await handle_message(user_id, transcript)
        elif text:
            await handle_message(user_id, text)
    
    return {"ok": True}

async def handle_message(user_id, text):
    """
    Основной flow: парс → уточнение → подтверждение → запись в БД
    """
    
    # 1. Parse
    parsed = await parse_with_claude(text)
    
    # 2. Clarify
    if parsed['needs_clarification']:
        parsed = await clarify_missing_fields(parsed, user_id)
    
    # 3. Confirmation
    await show_confirmation(parsed)
    
    # 4. Wait for user confirmation
    confirmed = await wait_for_button_click(user_id)
    
    if confirmed:
        # 5. Save to DB
        transaction = await save_transaction(parsed, user_id)
        
        # 6. Handle business logic
        if parsed['is_offset']:
            await handle_offset_expense(transaction)
        if parsed.get('split_participants'):
            await handle_grouped_expense(transaction)
        
        # 7. Sync to Sheets (async)
        asyncio.create_task(sync_to_sheets())
        
        await send_telegram_message(user_id, "✅ Операция записана!")
    else:
        await send_telegram_message(user_id, "❌ Отменено")

async def handle_command(user_id, command):
    if command == '/balance':
        balance = await get_counterparty_balances()  # (будущее для взаимозачётов)
        msg = format_balance(balance)
        await send_telegram_message(user_id, msg)
    
    elif command == '/debts':
        debts = await get_debt_summary()
        msg = format_debts(debts)
        await send_telegram_message(user_id, msg)
    
    elif command.startswith('/export'):
        dates = parse_export_command(command)  # "2025-08-01:2025-08-31"
        file = await generate_xlsx(dates)
        await send_telegram_file(user_id, file)
```

## Безопасность

- **Аутентификация:** telegram_id проверяется перед любой операцией
- **API-ключи:** Все (Claude, Telegram, Google Sheets, Supabase) в .env
- **Логирование:** Все парсинги ИИ в raw_ai_log для аудита
- **HTTPS/TLS:** Все интеграции через защищенные каналы

## Масштабируемость

- **Кеширование:** Справочники (категории, объекты) в памяти, обновление раз в час
- **Async обработка:** Синхронизация Sheets не блокирует ответ пользователю
- **Batch-операции:** Если операций >10, batch-вставка в Sheets
- **Архитектура:** Готова к добавлению RBAC, дополнительных координаторов без изменения БД
