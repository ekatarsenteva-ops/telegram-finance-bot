## РЕШЕНИЯ ПО АРХИТЕКТУРЕ (на основе выбранных ответов)

| Аспект | Решение | Обоснование |
|--------|---------|-----------|
| **Структура категорий** | Отдельный справочник по объектам | Чистая архитектура, нет путаницы между объектами |
| **Контрагенты** | Глобальные, без привязки к объекту | Один человек может быть контрагентом в разных объектах |
| **Отслеживание возврата** | Флаг `is_paid` в `expense_participants` | На текущем этапе проста, расширяется на будущее |
| **Типы операций** | 3 типа: приход, платёж, расход | Гибкость для взаимозачётов и групповых расходов |
| **Google Sheets** | Read-only витрина, архитектура готова для B | Двусторонняя синхронизация отложена на будущее |
| **Аудит** | raw_ai_log + created_at | Достаточно для отладки парсинга ИИ |
| **Экспорт** | Только по периоду (даты) | Самый простой вариант, расширяется позже |
| **Локализация** | Архитектура готова, пока русский | Легко добавить i18n позже |
| **Уведомления** | Нет | Система реактивна, не проактивна |
| **Бэкапы** | Supabase native | Достаточно ежедневных бэкапов |

## СТЕК ТЕХНОЛОГИЙ

- **Backend:** Python 3.10+
- **Веб-фреймворк:** FastAPI (async/await для webhook'ов)
- **БД:** PostgreSQL (Supabase или Docker)
- **БД ODM:** psycopg3 или SQLAlchemy
- **Telegram:** python-telegram-bot или aiogram
- **AI парсинг:** Claude API (anthropic SDK)
- **STT:** (опционально) Yandex SpeechKit или Whisper
- **Google Sheets:** google-sheets-api (via Service Account)
- **Экспорт Excel:** openpyxl или pandas
- **Логирование:** logging (Python стандартный)
- **Конфиги:** python-dotenv для .env переменных

## ПРИМЕРЫ CLAUDE PROMPTS

### Основной промпт (парсинг операций)

```python
PARSE_SYSTEM_PROMPT = """
Ты помощник для учета финансов. Твоя задача - парсить финансовые операции из естественного текста.

Выпиши всегда JSON с полями:
{
  "transaction_type": "income" | "expense" | "incoming_payment",
  "amount": number (сумма в рублях или другой валюте),
  "currency": "RUB" | "USD" | "EUR" | null,
  "date": "YYYY-MM-DD" (если не указано, используй текущую дату),
  "counterparty": "строка имени/компании" | null,
  "organization_id": 1 (Школа) | 2 (Недвижимость) | null,
  "category": "строка категории" | null,
  "is_offset": boolean (есть ли зачет в аренду или скидка?),
  "split_participants": [
    {"name": "Иван", "amount": 3000},
    {"name": "Мария", "amount": 3000},
    {"name": "Петр", "amount": 3000}
  ] | null,
  "confidence": 0-100 (уверенность парсинга),
  "needs_clarification": ["field1", "field2", ...] (какие поля нужны уточнения?)
}

Правила:
1. Тип операции:
   - "income": свободный приход (пришло, получил, зачислилось)
   - "incoming_payment": плановый платёж (платеж, взнос, аренда)
   - "expense": расход (купил, потратил, расход)

2. Взаимозачёты (is_offset = true):
   - текст содержит "зачет", "вычту", "скидка на", "против платежа"

3. Деление расходов:
   - текст содержит "делим на", "поровну", "на каждого", "между"
   - калькулировать сумму на человека (total / count)

4. Объект:
   - "школа", "язык", "обучение" → организация 1 (Школа)
   - "недвижимость", "аренда", "квартира", "дом" → организация 2 (Недвижимость)

5. Валюта:
   - "рублей", "рубль" → RUB
   - "долл", "баксов" → USD
   - "евро" → EUR
   - не указана → null (по умолчанию RUB)

Примеры парсинга:
- "Пришло 15000 от Пети" →
  {transaction_type: "income", amount: 15000, currency: "RUB", counterparty: "Петя", 
   date: "2025-08-01", needs_clarification: ["organization_id"]}

- "Внесли аренду за август, 50 тыс" →
  {transaction_type: "incoming_payment", amount: 50000, currency: "RUB", 
   category: "Аренда", organization_id: 2, needs_clarification: ["counterparty"]}

- "Куплю материал для школы за 6 тыс, зачет в аренду" →
  {transaction_type: "expense", amount: 6000, is_offset: true, organization_id: 1,
   needs_clarification: ["category", "counterparty"]}

- "Пикник на школе 9 тыс, делим поровну на Иву Марию Петра" →
  {transaction_type: "expense", amount: 9000, organization_id: 1,
   split_participants: [{name: "Ива", amount: 3000}, {name: "Мария", amount: 3000}, 
   {name: "Петр", amount: 3000}], needs_clarification: ["category"]}
"""

USER_PROMPT = "Распарси операцию: {user_text}"
```

## ПРИМЕЧАНИЯ ДЛЯ РАЗРАБОТКИ

1. **Async/Await везде:** FastAPI + aiogram/python-telegram-bot для асинхронности
2. **Graceful shutdown:** При остановке приложения закрыть соединения с БД
